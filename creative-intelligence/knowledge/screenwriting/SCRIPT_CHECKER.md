# SCRIPT_CHECKER — กฎตรวจบท (VO / บทสนทนา / caption) ที่เครื่องมือใช้ได้

ใช้ได้กับทุกสาขา/ลูกค้า ทฤษฎีและแหล่งอ้างอิง: `README.md` + `sources.json` ในโฟลเดอร์นี้
โครงเรื่อง/beat ตามความยาว → `knowledge/storytelling/STORY_TEMPLATES.md` · จุดตรวจ retention → `knowledge/audience/RETENTION_REVIEW.md` · normalise ภาษาไทยสำหรับ TTS → `knowledge/thai-language/NORMALIZATION_RULES.md` · ตรวจข้อเท็จจริงสายตา → `knowledge/optical/FACT_CHECK_WORKFLOW.md`

**ป้ายหลักฐาน:** `SCI-S/A/B` = งานวิจัย (tier) · `GUIDE` = แนวทางทางการ · `CRAFT` = แนวปฏิบัติคนทำงาน · `DERIVED` = อนุมาน/วัดเอง
**ระดับผล:** `FAIL` ต้องแก้ก่อนส่ง · `WARN` ให้คนตัดสิน · `INFO` ข้อสังเกต
**หลักการ:** threshold ทั้งหมดเป็นจุดเตือน ไม่ใช่การทำนายผล — message design ทุกแบบมีผลเล็กและไม่แน่นอน `[OKeefeHoeken2021]`

---

## Input ที่ตัวตรวจต้องการ
```
script: [{id, speaker, spoken, subs, beat, start_s?, end_s?}]   # spoken = ข้อความที่ TTS อ่าน, subs = ซับบนจอ
meta:   {target_duration_s, audience_age?, purpose: story|promo|education|health|announcement,
         hook_text, cta_text, claims: [..], lang: th|en, audio_dir?}
```
แบ่งคำภาษาไทย: ใช้ตัวตัดคำ (เช่น PyThaiNLP — ยังไม่ได้ติดตั้งในเครื่องนี้) ถ้าไม่มี ใช้ **จำนวนตัวอักษรไทย** (U+0E00–U+0E7F) เป็นหน่วยสำรอง และ "ประโยค" = แต่ละ cue/บรรทัด หรือแบ่งด้วย `. ! ? …` และเว้นวรรค

---

## R1. Duration fit — VO พอดีกับวิดีโอไหม  *(สำคัญที่สุด)*
**วิธีหลัก (บังคับ):** วัดจากไฟล์เสียง TTS จริง ไม่ใช่ประมาณ
- ความยาวต่อ cue = `frames / framerate` ของ wav (หรือ `ffprobe -show_entries format=duration`) ; ตัดเงียบหัวท้ายก่อนวัดถ้า split ทิ้งไว้
- `total_vo = Σ cue + Σ ช่วงเว้น` ; เทียบกับ `target_duration_s`

| เงื่อนไข | ผล |
|---|---|
| total_vo > target − 0.5 s (ไม่มีที่ให้ end card/โลโก้หายใจ) | FAIL |
| cue ใดยาวกว่า beat/ช็อตที่วางไว้ > 0.3 s | FAIL |
| total_vo < 60% ของ target ในคลิปที่มี VO นำ | WARN (ช่องว่างยาว/ภาพต้องเล่าเอง) |
| ต้องเร่ง TTS > 1.15× เพื่อให้พอดี | WARN; ผู้ชม 40+ → FAIL ให้ตัดบทแทน — ผู้ฟังสูงวัยไวต่อเสียงเร็ว `[Wingfield1999]` (SCI-A) ; ค่า 1.15× = CRAFT |
- เหตุผล: ประโยคสั้น 1–7 คำถูกพูดเร็วกว่าต่อคำ และส่วนสำคัญถูกพูดช้าลง `[YuanLibermanCieri2006]` → การคูณอัตราคงที่ผิดได้ต่อบรรทัด (SCI-A)

**วิธีสำรอง (ตอนร่างบท ยังไม่มีเสียง):**
- **ภาษาไทย (DERIVED, วัด 2026-11-25):** TTS ของสตูดิโอ (Gemini voice Puck) ≈ **10.7–13.0 ตัวอักษรไทย/วินาที** (ต่อบรรทัด 8.6–16.0) จาก 51 บรรทัด 3 kit → ประมาณ `เวลา ≈ ตัวอักษรไทย ÷ 11` + ช่วงเว้นระหว่าง cue (ค่าที่ kit ใช้ ~0.25–0.45 s) ; ใช้ ÷ 10 สำหรับเสียงช้า/อบอุ่น/ผู้ชมสูงวัย. ค่านี้มาจากเสียงเดียว (Puck) — เมื่อใช้เสียงอื่น (เช่น Sulafat) ให้วัดใหม่จาก 5–10 บรรทัดแรกแล้วแทนค่า
- **ข้ามภาษา (SCI-A):** อ่านออกเสียงเฉลี่ย 6.63 พยางค์/วินาที (SD 1.15; ผู้พูด 4.3–9.1) ไม่นับช่วงเงียบ >150 ms; ไทยอยู่กลุ่มอัตราช้ากว่า (แหล่งรอง) — **ค่าภาษาไทยเฉพาะยังไม่ยืนยัน** `[Coupe2019]` `[CNRS2019]` → ถ้านับพยางค์ได้ ใช้ ~5–6.5 พยางค์/s เป็นกรอบหยาบ (DERIVED)
- **ภาษาอังกฤษ:** สนทนาโทรศัพท์ ~152–170 wpm ตามหัวข้อ (turn-wise 164) `[YuanLibermanCieri2006]` (SCI-A, เป็นบทสนทนา ไม่ใช่บรรยาย) ; ค่าบรรยาย 130–160 wpm ที่พบทั่วไปเป็น lore/CRAFT ไม่ได้ตรวจแหล่ง
- ผลจากวิธีสำรองเป็นได้แค่ `WARN` — FAIL ต้องมาจากเสียงจริง

## R2. Too written-style? (ภาษาเขียนเกินไป)
นับสัญญาณต่อ cue; flag เมื่อ ≥2 สัญญาณใน cue เดียว หรือ ≥30% ของ cue มีสัญญาณ (DERIVED จาก `[Biber1988]` ว่าความเป็นภาษาเขียนเป็นกลุ่มลักษณะ)
- คำเชื่อม/ศัพท์ทางการ (ไทย): ดังกล่าว, อนึ่ง, ทั้งนี้, โดยมี, ซึ่งได้, อันเป็น, ในการที่จะ, ดำเนินการ, กระทำการ, เพื่อให้เกิด, ณ, ฯลฯ, ตลอดจน (ปรับรายการได้)
- คำนามจากกริยาซ้อน: "การ…ความ…" ≥2 ครั้งในประโยค
- วงเล็บ, อักษรย่อไม่ได้ขยาย, ตัวเลขยาว ≥4 หลักที่ไม่ปัด, เครื่องหมาย `;` `:` `/` — ใช้แค่จุลภาค/มหัพภาค และปัดตัวเลข `[MediaHelpingMedia2026]` (CRAFT)
- passive ("ถูก…โดย…") ในข้อความหลัก/CTA → WARN; CDC ให้ main message และ CTA เป็น active `[CDC_CCI]` (GUIDE)
- **ทดสอบอ่านออกเสียง:** ทุกบทต้องผ่านการอ่านออกเสียง 1 รอบโดยคน — มีจุดหายใจไม่ทัน/ลิ้นพันกันไหม `[MediaHelpingMedia2026]` (CRAFT, ข้อบังคับ manual)

## R3. Sentences too long? (ประโยคยาวเกิน)
| หน่วย | threshold | ผล | หลักฐาน |
|---|---|---|---|
| ภาษาอังกฤษ (เขียน/caption) | เฉลี่ย >20 คำ หรือประโยคใด >40 คำ | WARN / FAIL | GUIDE `[FedPlainLanguage]` |
| ภาษาอังกฤษ (VO) | ประโยคใด >25 คำ | WARN | CRAFT (หูฟังได้ครั้งเดียว — สั้นกว่าการเขียน) |
| ภาษาไทย (VO, ต่อ cue ที่วัดเสียงจริง) | cue > 6 s | WARN ; > 8 s FAIL | CRAFT/DERIVED (≈ ช่วงหายใจ + ซับ 2 บรรทัด; ไฟล์ต่อบรรทัดในชุดวัดยาว 1.1–6.8 s รวมเงียบหัวท้าย) |
| ภาษาไทย (สำรอง ไม่มีเสียง) | cue > 66 ตัวอักษรไทย (~6 s ที่ 11 ตัว/s) | WARN | DERIVED |
| ทุกภาษา | >1 ความคิดหลักต่อประโยค (มี "และ/แต่/ซึ่ง/เพราะ" เชื่อม ≥2 ครั้ง) | WARN | GUIDE "one idea per sentence" `[FedPlainLanguage]` |

## R4. Information too dense? (ข้อมูลแน่นเกิน)
- นับ "หน่วยข้อมูลใหม่" ต่อ cue (ตัวเลข, ชื่อเฉพาะ, ศัพท์เทคนิค, ข้อเท็จจริง/ข้อกล่าวอ้าง)
  - > 2 ต่อ cue → WARN ; > 1 ศัพท์เทคนิคที่ไม่อธิบายต่อ cue → WARN (CRAFT; สอดคล้อง plain language `[GOVUK_Writing]` "อธิบายศัพท์ที่จำเป็น")
- ข้อความหลัก: ต้องมี **1** ข้อความหลักที่เป็นประโยค (ไม่ใช่หัวข้อ) และอยู่ใน 25% แรกของบท → ไม่มี = FAIL (สำหรับ health/education/promo) `[CDC_CCI]` (GUIDE)
- ตัวเลขความเสี่ยง: เปอร์เซ็นต์ลดความเสี่ยงแบบ relative ที่ไม่มีฐาน → FAIL ในงานสุขภาพ; แนะนำ natural frequency "X ใน 100 คน" `[Akl2011]` (SCI-S)
- ผู้ชมสูงวัย/เนื้อหาสุขภาพ: ต้องมีช่วงหยุด ≥0.4 s หลังข้อเท็จจริงสำคัญ → ไม่มี = WARN (การเว้นช่วยผู้ฟังสูงวัย `[Wingfield1999]` SCI-A; ค่า 0.4 s = CRAFT)

## R5. Repeated words (คำซ้ำ)
- คำเนื้อหาเดียวกัน (ไม่นับคำไวยากรณ์/คำลงท้าย) ซ้ำ ≥3 ครั้งใน 3 cue ติดกัน → WARN (CRAFT)
- **ยกเว้น:** ชื่อแบรนด์/คำ CTA ที่ตั้งใจซ้ำ (เช่น ชื่อร้านพูด 2–3 ครั้งในคลิป 60 s), anaphora ที่ตั้งใจ ("ตื่นมาก็ใส่ ทำงานก็ใส่ ขับรถก็ใส่") → ติดป้าย `intentional` ใน meta เพื่อข้าม
- ซับกับ VO เหมือนกันทุกตัวอักษร และ cue > 8 คำ/40 ตัวอักษร → INFO: พิจารณาซับแบบย่อ — ข้อความตรงทุกคำกับเสียงอาจลดการเรียนรู้ ส่วน keyword ช่วย `[AdesopeNesbit2012]` `[YueBjorkBjork2013]` (SCI-S/A; ซับเพื่อ accessibility ยังคงจำเป็น `[Gernsbacher2015]`)

## R6. Filler (คำฟุ่มเฟือย)
- **VO บรรยาย:** "เอ่อ, อืม, แบบว่า, คือแบบ, ก็คือว่า, จริง ๆ แล้วก็, เรียกได้ว่า, อย่างที่บอก" → แต่ละคำ = WARN (เพิ่มเวลาไม่เพิ่มความหมาย; CRAFT)
- **บทพูดตัวละคร:** filler/discourse marker ≤1 ต่อ turn ยอมรับ (ทำให้ฟังเป็นภาษาพูดและสื่อความลังเล `[ClarkFoxTree2002]` SCI-A) ; >1 ต่อ turn ติดกันหลาย turn → WARN
- **ห้ามตัดคำลงท้ายทางสังคม** (ครับ/ค่ะ/นะ/จ้ะ) แบบเหมารวม — มันกำหนดน้ำเสียงและความสุภาพ (DERIVED)
- intensifier ซ้อน ("มาก ๆ ๆ", "สุด ๆ จริง ๆ") ≥2 ใน cue → INFO

## R7. Dialogue sounds spoken? (เฉพาะบทสนทนา)
- turn ยาว > 2 ประโยค หรือ > 6 s (เสียงจริง) โดยไม่มีอีกฝ่ายแทรก → WARN (turn-taking จริงเป็น turn สั้น recipient-designed `[SacksSchegloffJefferson1974]` SCI-A; threshold = CRAFT)
- ช่องว่างระหว่างผู้พูดใน mix > 0.7 s โดยไม่ตั้งใจ → WARN (ทุกภาษาลดความเงียบระหว่าง turn; ความเงียบยาวถูกอ่านว่ามีปัญหา `[Stivers2009]` SCI-A; ค่า 0.7 s = CRAFT)
- "As you know" exposition: ตัวละครบอกข้อมูลที่ผู้ฟังในเรื่องรู้แล้ว → WARN (CRAFT `[McKee2016]`)
- บทพูดบอกอารมณ์ตรง ("ฉันเสียใจมาก") ในจุด climax → INFO: ลอง subtext (CRAFT)
- Voice test: ปิดชื่อผู้พูดแล้วแยกตัวละครได้ไหม (คำติดปาก ความยาว turn คำลงท้าย) → manual

## R8. Emotional beats (จังหวะอารมณ์)
- ทุก cue ต้องมีป้าย valence (−2…+2) จากผู้เขียนหรือ classifier → สร้างเส้นอารมณ์
  - เส้นแบน (ทุก cue เท่ากัน) ในคลิป story ≥15 s → WARN (โครงที่มี suspense/surprise ถูกชอบมากกว่าลำดับเหตุการณ์เรียบ ๆ `[BrewerLichtenstein1981]` — ดู M13)
  - ไม่มี resolution (cue สุดท้ายไม่คลี่คลายและไม่มีป้าย `series_cliffhanger`) → FAIL สำหรับ story
  - promo/ad: ควรมีจุดบวกภายใน 30% แรก → INFO (joy ช่วยการดูต่อในโฆษณาออนไลน์ `[Teixeira2012]` — แหล่งอยู่ใน M13 sources)
- รูปเส้นที่ตั้งใจ (Man in a hole ฯลฯ) ระบุใน meta แล้วตรวจว่าตรง → INFO

## R9. Hook matches content? (hook ตรงเนื้อหาไหม)
- ดึงคำสำคัญ/คำสัญญาใน hook (cue แรก หรือ `hook_text`, ปกคลิป, caption บรรทัดแรก)
  - คำสัญญานั้นต้องถูก "จ่ายคืน" (คำ/แนวคิดเดียวกันปรากฏในเฉลย) ภายในคลิปเดียวกัน → ไม่พบ = FAIL
  - hook แบบ forward-reference ("สิ่งนี้…", "เคล็ดลับเดียว…", "คุณจะไม่เชื่อ…", "ไม่มีใครบอกคุณ…") → WARN: ต้องจ่ายคืนภายใน 50% แรกของคลิป (pattern ตาม `[BlomHansen2015]` SCI-A; ตำแหน่ง 50% = CRAFT)
  - คำเกินจริง (ดีที่สุด, 100%, หายขาด, ทันที) → FAIL สำหรับสุขภาพ/การแพทย์ (ดู `marketing/ETHICS_AND_THAI_AD_RULES.md`)
- เหตุผล: clickbait ลดความน่าเชื่อถือได้เล็กน้อย `[MolyneuxCoddington2020]` แต่บางการทดลองไม่พบผล `[Munger2020]` → ประเด็นหลักคือความซื่อตรง ไม่ใช่ผลคลิก (SCI-A, contested)
- **ไม่มี rule "hook ต้องมีตัวเลข/คำถาม"** — ไม่มีหลักฐานว่าเป็นสูตร `[Matias2021]` `[OKeefeHoeken2021]`

## R10. Continuity (ความต่อเนื่อง)
- ชื่อ/สรรพนาม/เพศ/คำลงท้ายของตัวละครเดียวกันคงที่ตลอด (เช่น Tao ใช้ "ผม/ครับ" ทั้งเรื่อง) → เปลี่ยน = FAIL (DERIVED)
- ตัวเลข/ราคา/วัน ที่ปรากฏหลายครั้งต้องตรงกันทั้ง VO, ซับ, caption, ภาพ → ไม่ตรง = FAIL
- setup/payoff: สิ่งของ/ปัญหาที่ตั้งไว้ใน 30% แรกต้องกลับมา; payoff ต้องมี setup → WARN (CRAFT, M13 §2.11)
- `spoken` vs `subs` ต้องสื่อความเดียวกัน (ซับย่อได้ แต่ห้ามเปลี่ยนความหมาย/ตัวเลข) → FAIL
- ข้ามตอนในซีรีส์: เทียบกับ series bible/ตอนก่อน (manual)

## R11. Facts correct? (ข้อเท็จจริงถูกไหม)
- ดึงทุก claim (ตัวเลข, ผลทางสุขภาพ, เปรียบเทียบ, "งานวิจัยบอกว่า") ไปใส่ `meta.claims`
  - claim สายตา/สุขภาพที่ไม่มี reference ใน `knowledge/optical/claims_library.json` หรือไม่ผ่าน FACT_CHECK_WORKFLOW → FAIL
  - claim ที่ตรงกับ myth list → FAIL: "เรื่องเล่าจำได้ 22 เท่า", "oxytocin ทำให้เชื่อใจแบรนด์", "สมาธิปลาทอง 8 วินาที" (ดู M13 README §3)
  - relative risk ไม่มีฐาน → FAIL (R4)
- เรื่องเล่าแพร่ข้อมูลผิดได้ `[Dahlstrom2014]` (M13 sources) → ข้อเท็จจริงต้องถูก "tell" ชัด ไม่ซ่อนในบทพูดกำกวม
- ผลอ่านง่ายขึ้นช่วยความเข้าใจ แต่ไม่รับประกันพฤติกรรม `[Dunnett2025]` (SCI-S) → อย่าเขียนสัญญาผลลัพธ์

## R12. CTA appropriate? (CTA เหมาะไหม)
| เงื่อนไข | ผล | หลักฐาน |
|---|---|---|
| purpose เป็น promo/health/education แต่ไม่มี CTA | FAIL | GUIDE `[CDC_CCI]` |
| CTA > 1 แบบ (ทัก + โทร + ลิงก์ + แชร์) | WARN | CRAFT |
| CTA ไม่ใช่พฤติกรรมเฉพาะ ("มาดูแลสายตากันนะ" ไม่บอกทำอะไร ที่ไหน) | WARN | GUIDE `[CDC_CCI]` |
| CTA เป็น passive / มุ่งคนอื่นที่ไม่ใช่ผู้ชมหลัก | WARN | GUIDE `[CDC_CCI]` |
| CTA อยู่กลางเรื่องก่อน resolution (story) | WARN | DERIVED (ไม่ตัด transportation — M13) |
| CTA ใช้ความกลัว/เร่งด่วนเกินจริงทางสุขภาพ | FAIL | `marketing/ETHICS_AND_THAI_AD_RULES.md` |
| health message แบบ "เลิกทำ X" ล้วนในคลิปเล่าเรื่อง | INFO: เปลี่ยนเป็น "ทำ Y แทน / ไปตรวจ" | SCI-S `[ShenSheerLi2015]` |
| promo ที่ต้องมีราคา/โปร แต่ไม่ได้ถามผู้ใช้ | FAIL | กฎบ้าน (CLAUDE.md: ถามราคา/โปรทุกครั้ง) |

## R13. Caption / microcopy (โพสต์และข้อความบนจอ)
- caption บรรทัดแรก ≤ ~125 ตัวอักษร (ก่อน "…เพิ่มเติม") และต้องผ่าน R9 → INFO (CRAFT; ค่าการตัดของแต่ละแพลตฟอร์มเปลี่ยนได้ — ไม่ได้ตรวจแหล่งรอบนี้)
- ซับบนจอ ≤ 2 บรรทัดต่อ cue, อยู่ใน safe zone (ดู memory "IG Reels 9:16") → เกิน = WARN (CRAFT)
- ข้อความบนจอที่ไม่ใช่ซับ = keyword ≤ 5 คำ ไม่แข่งกับซับ `[AdesopeNesbit2012]` (SCI-S, บริบทการเรียนรู้)

## ลำดับการรัน (pipeline)
1. Normalise ข้อความไทยสำหรับ TTS (thai-language module) → `spoken`
2. R2–R7 บนข้อความ (เร็ว ไม่ต้องมีเสียง) + R1 วิธีสำรอง → แก้บท
3. R9–R12 (hook, continuity, facts, CTA) → แก้บท
4. สร้าง TTS (ถามผู้ใช้ก่อนถ้าใช้ quota) → **R1 วิธีหลักจากไฟล์เสียง** + R7 (ช่องว่างใน mix) + R4 (ช่วงหยุด)
5. R8 เส้นอารมณ์ + R13 caption → รายงาน
6. อ่านออกเสียง/ฟังรอบสุดท้ายโดยคน (บังคับ — ตัวตรวจอัตโนมัติไม่แทนการฟัง)
