# Story Bible — template (ใช้กับซีรีส์ใดก็ได้: คลิปเรื่อง, carousel, แคมเปญแบรนด์, mascot)

ก๊อปไฟล์นี้ไปเป็น `<series-folder>/SERIES.md` แล้วกรอก. ยิ่งซีรีส์สั้น ยิ่งกรอกน้อย — ชั้น 1 จำเป็นเสมอ, ชั้น 2 โตตามจำนวนตอน, ชั้น 3 ต่อตอน.
โครงมาจาก series bible ในงาน TV (premise, place, characters, rationale, structure & style, research, case law, episodes — Macdonald2018)
และทฤษฎีโลก (Wolf: invention/completeness/consistency; minimal departure — Ryan). เหตุผลอยู่ใน `README.md` ของ M16.

> **กติกา 4 ข้อ**
> 1. Bible คือ "DNA" ไม่ใช่ "แผ่นศิลา" — แก้ได้ แต่ทุกครั้งที่แก้ให้ขึ้น version และบันทึกว่าแก้อะไร
> 2. แยก **canon** (ออกอากาศแล้ว) กับ **planned** (ยังไม่ออก) ทุกจุด
> 3. รู้มากกว่าที่แสดง (iceberg) — แต่ทุกอย่างที่เขียนในนี้ต้อง "ใช้ได้จริง" ไม่ใช่ lore ประดับ
> 4. ข้อมูลที่ต้องตรวจได้ด้วยเครื่อง (ตัวละคร looks, props, timeline, rules) อยู่ใน `continuity.json` (M38: `../continuity/CONTINUITY_SYSTEM.md`) — ไฟล์นี้เป็นฉบับอ่านง่าย อย่าเขียนข้อมูลเดียวกันสองที่ ให้ลิงก์ไป

## ชั้น 1 — DNA (นิ่ง; 1–2 หน้า)

### 1.1 ข้อมูลซีรีส์
| | |
|---|---|
| ชื่อ (TH / EN) | |
| Series ID (ใช้เป็น prefix ทุก entity) | เช่น `zombie`, `slowly` |
| รูปแบบ | 9:16 คลิป __ วินาที / IG 1:1 carousel __ สไลด์ / ... |
| ภาษา / ซับ / เสียง | |
| ประเภท | serial (สถานะต่อเนื่อง) / anthology (แค่ format ต่อเนื่อง) / episodic / campaign |
| ช่องทาง & บทบาทของแต่ละช่อง | เช่น คลิป = เรื่องหลัก, carousel = เบื้องหลัง/ข้อมูล, คอมเมนต์ปักหมุด = แหล่งอ้างอิง (additive แต่ทุกชิ้นจบในตัว — Jenkins2007) |
| แบรนด์ในงาน | มี/ไม่มีโลโก้, ตำแหน่ง, end card |
| เจ้าของ / ผู้อนุมัติ | |
| Version / อัปเดตล่าสุด | v__ · YYYY-MM-DD |

### 1.2 Premise (1–2 บรรทัด)
> [ใคร] ต้อง [ทำอะไร] ใน [โลก/สถานที่] เพราะ [แรงขับ] แต่ [อุปสรรค]

### 1.3 ทำไมต้องเรื่องนี้ / ตอนนี้ (rationale)
- คนดูคือใคร ต้องการอะไรจากซีรีส์ (อารมณ์ ความรู้ ความบันเทิง)
- touchstones: "A ผสม B" (ระบุเฉพาะ format ที่ยืม — ห้ามลอกเรื่อง/ตัวละคร)

### 1.4 โลก: ต่างจากโลกจริงตรงไหน (minimal departure)
ทุกอย่างที่ไม่ได้เขียนไว้ = เหมือนโลกจริง (ประเทศไทยปัจจุบัน, เวลาเดินปกติ, คนต้องกิน/นอน/เดินทาง)
| ระดับ (Wolf) | สิ่งที่เปลี่ยน | ตั้งขึ้นใน EP |
|---|---|---|
| nominal (ชื่อ, คำเฉพาะ) | | |
| cultural (สังคม, ธรรมเนียม) | | |
| natural (สิ่งมีชีวิต, ธรรมชาติ) | | |
| ontological (กฎจักรวาล: ผี, เวทมนตร์, ซอมบี้) | | |
| สไตล์ภาพที่ไม่ใช่ "กฎโลก" (เช่น ตัวละครหน้าว่าง, ลายดินสอ) | | |

**External realism ที่ห้ามผิด** (สิ่งจริงที่คนดูรู้): สถานที่จริง, ราคา, ข้อเท็จจริงวิทยาศาสตร์/สุขภาพ (ใส่แหล่งอ้างอิง), ภาษา/สำนวน

### 1.5 กฎพิเศษ (rules, costs, limits)
| กฎ | ต้นทุน/ข้อจำกัด | ระบบ hard/soft | ใช้แก้ปมได้? (ต้องปูก่อน) | ตั้งขึ้นใน EP |
|---|---|---|---|---|
| | | | | |
- Soft system = ใช้สร้างบรรยากาศ ไม่ใช่แก้ปม; Hard system = แก้ปมได้เมื่อคนดูเข้าใจแล้ว (Sanderson2007 — craft)
- ห้ามเพิ่มกฎใหม่เพื่อแก้ปมเฉพาะหน้า

### 1.6 Tone & style
- อารมณ์หลัก / อารมณ์ที่ห้าม
- ความยาว, จังหวะ, โครงสร้างต่อตอน (เช่น hook 3 วิ → ... → cliffhanger)
- ภาพ: ลิงก์ style guide / master refs (`_refs/`) — รายละเอียดการออกแบบฉากดู `ENVIRONMENT_DESIGN.md`
- เสียง: ลิงก์ voice bible (`CHARACTER_VOICE_BIBLE.md`)

### 1.7 Never list (สิ่งที่ซีรีส์นี้ไม่ทำ)
- เนื้อหา/มุก/ภาพที่ห้าม, ข้อห้ามแบรนด์, ข้อห้ามทางวัฒนธรรม

## ชั้น 2 — Case law (โตทุกตอน; ข้อมูลตรวจได้อยู่ใน `continuity.json`)

### 2.1 ตัวละครหลัก (สรุป — รายละเอียดภาพใน CHARACTER_BIBLE, ข้อมูลตรวจใน continuity.json)
| ID | ชื่อ | บทบาท | ต้องการ (want) / กลัว (fear) | นิสัยที่คนดูจะจำ | ไม่เคยทำ | identity markers (3–6) | ฝั่งจอ |
|---|---|---|---|---|---|---|---|
| | | | | | | | |
- ความสัมพันธ์ (ใคร–ใคร: รัก/ขัดแย้ง/ติดหนี้) — แหล่งความขัดแย้งในตัวที่ใช้เขียนตอนใหม่ได้ไม่รู้จบ
- **สิ่งที่แต่ละคนรู้** — ตัวละครแต่ละคนมี "โลกส่วนตัว" ของความรู้/ความต้องการ (Ryan2012PW); ความต่างระหว่างสิ่งที่คนดูรู้กับตัวละครรู้ = suspense

### 2.2 สถานที่ประจำ
| ID | ชื่อ | จริง/สมมติ | ผังคงที่ (ประตู/หน้าต่างอยู่ไหน, ทิศ "ออก" บนจอ) | แสง/ช่วงเวลา | ร่องรอยที่เล่าเรื่อง (embedded) | master ref |
|---|---|---|---|---|---|---|
- ช็อตเปิดของแต่ละสถานที่ต้องตอบ "ที่ไหน" ได้ทันทีจากภาพ (Carson2000)
- Embedded narrative: วัตถุที่เล่าอดีตแทนการบรรยาย — ซ้ำอย่างน้อย 2 จุดเพราะคนดูพลาดได้ (Jenkins2004)

### 2.3 ของสำคัญ (hero props)
| ID | ของ | เจ้าของ | ความหมายในเรื่อง | สถานะปัจจุบัน |
|---|---|---|---|---|

### 2.4 ไทม์ไลน์
- ไทม์ไลน์ของโลก (ก่อนเรื่องเริ่ม — backstory ที่รู้แต่ไม่ต้องแสดง)
- ไทม์ไลน์ในเรื่อง (ต่อตอน) → `continuity.json › timeline`

### 2.5 Running elements
| มุก/คำติดปาก/motif/format device | กติกาการเล่นซ้ำ (ยกระดับ/กลับด้าน/พัก) | ใช้ล่าสุด EP |
|---|---|---|

### 2.6 ปริศนาและปมที่เปิดไว้ (mystery budget)
- เปิดพร้อมกันไม่เกิน 1–2 ข้อ; ทุกข้อมีแผนจ่าย หรือบันทึกว่าตั้งใจทิ้ง (Wolf: enigma ต้องใช้น้อย มีข้อมูลโลกพอก่อน)

| ปม | ปูใน EP | แผนจ่าย EP | สถานะ |
|---|---|---|---|

### 2.7 Research & แหล่งอ้างอิง
- ข้อเท็จจริงจริงที่ซีรีส์ใช้ + แหล่ง (สำหรับซีรีส์ความรู้ เช่น eyesight: ใส่ source key จาก `creative-intelligence`)

### 2.8 การสะกด/ออกเสียง
| ไทย | อังกฤษ | วิธีอ่าน TTS |
|---|---|---|

## ชั้น 3 — ตอน (episode layer)

### 3.1 Arc ของซีซัน
- จุดเริ่ม → จุดกลาง → จุดจบ; แต่ละตอนเปลี่ยนอะไรในโลก/ตัวละคร

### 3.2 รายการตอน
| EP | ชื่อ | สถานะ | สรุป 1 บรรทัด | สิ่งใหม่ที่เพิ่มให้โลก (additive) | สิ่งที่เปลี่ยน (state) | tease ตอนถัดไป |
|---|---|---|---|---|---|---|
- ทุกตอน: เพิ่มข้อมูลโลก 1–3 ข้อ แต่คนดูใหม่ต้องดูรู้เรื่อง (Jenkins2007: additive comprehension vs accessibility)

### 3.3 ตอนตัวอย่าง (สำหรับซีรีส์ใหม่)
- บท/outline ของตอนแรก 1 ตอน เพื่อพิสูจน์ว่า DNA ใช้ได้จริง

## ตัวอย่างการกรอกสั้นๆ (ซีรีส์สมมติ ไม่ใช่ของจริง)
- Premise: "เจ้าของร้านขนมปังเล็กๆ ในตลาดเช้า ต้องช่วยลูกค้าหนึ่งคนต่อตอนแก้ปัญหาชีวิตด้วยขนมปังหนึ่งชิ้น แต่ร้านกำลังจะถูกไล่ที่"
- ต่างจากโลกจริง: ไม่มี (realism) · สไตล์: สีน้ำ, ตัวละครหัวกลม
- กฎ: "ขนมปังไม่มีพลังวิเศษ" (กันการแก้ปมด้วยเวทมนตร์) · running element: แมวส้มขโมยขนมปังทุกตอน แต่วิธีขโมยยกระดับขึ้นเรื่อยๆ
- ปมใหญ่: การไล่ที่ (ปูใน EP1, จ่ายตอนจบซีซัน)
