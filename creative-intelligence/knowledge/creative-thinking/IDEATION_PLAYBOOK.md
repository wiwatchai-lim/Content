# Ideation Playbook — TIME OPTIC (Thai story carousels, story clips, product clips)

ป้าย: **EV** = มีหลักฐาน (key ใน `sources.json`) · **CRAFT** = แนวปฏิบัติ ไม่ได้ทดสอบ · ทุกขั้นตอนตั้งใจให้ทำได้ในหัวของ Claude + 1 ข้อความถึงผู้ใช้

## 1. หลักใหญ่ 5 ข้อ
1. **แยกเฟส:** สร้างหลายแนว (ห้ามตัดสิน) → เลือกด้วยเกณฑ์ → ขัดเกลา — EV [Guilford1950; Rietzschel2006; Girotra2010]
2. **คิดแยกก่อนรวม:** ร่างแต่ละทิศทางแยกกัน ไม่ต่อยอดจากทางแรก — EV nominal/hybrid > กลุ่มพูดพร้อมกัน; การต่อยอดไม่ช่วย [Mullen1991; DiehlStroebe1987; Girotra2010]
3. **คิดเองก่อนดู reference / ผลจาก AI** — EV fixation [JanssonSmith1991 — replicate ปนกัน]
4. **ทำหยาบหลายตัวคู่ขนาน ก่อนขัดตัวเดียว** — EV parallel prototyping [Dow2010]
5. **AI ยกพื้น แต่ดึงทุกคนเข้าหาค่าเฉลี่ย** → ต้องมีกลไกบังคับความต่าง — EV [DoshiHauser2024; Anderson2024; Meincke2024]

## 2. วิธีไหนเหมาะกับงานไหน
| งาน | วิธีหลัก | ทำไม / ป้าย |
|---|---|---|
| **เรื่อง Mint & Tao ใหม่** (Slowly Growing) | Morphological matrix: *สถานที่ × ความขัดแย้งเล็ก ๆ × ความรู้สึกที่เปลี่ยน × ภาพปิดท้าย* → เลือก 3 แถวที่ไม่ซ้ำค่ากันเลย | บังคับความต่างเชิงโครงสร้าง — CRAFT (วิธี [Ritchey2018], ไม่มีผลทดลอง) |
| **ข้อคิด/ปมของเรื่อง** | Analogy จาก 2 โดเมนที่ห่างกัน (เช่น ทำขนมครก ↔ การรอคอย) | ต้องสั่งหา analogy เอง คนไม่ทำเอง — EV [GickHolyoak1980; Mednick1962] |
| **คลิปสินค้าแว่น** (hook/มุม) | Constraint prompts: "ห้ามใช้ร้านกาแฟ/พระอาทิตย์ตก/หมุน 360°", "แว่นต้องเป็นตัวแก้ปัญหา", "ไม่มีคนในภาพ" | constraint ช่วยเมื่อดันออกจากค่าเริ่มต้น — EV ผลปนกัน [Acar2019] + CRAFT |
| **ภาพโปรโมท / visual metaphor** | Conceptual blend: input A = คุณสมบัติแว่น (บาง, กัน UV, ไทเทเนียม), input B = โลกหัวหิน (ทะเล, ว่าว, รถไฟ) → ภาพเดียวที่รวมความหมาย | [FauconnierTurner1998] theory — CRAFT ในการใช้ |
| **ปัญหาเทคนิค** (เลนส์บาง+แข็ง, ภาพแว่นดูว่าง) | TRIZ-style "ข้อขัดแย้ง → หลักแก้" | EV ในงานวิศวกรรม [VargasHernandez2013] |
| **ตรวจไอเดียจากหลายมุม** | Six hats แบบย่อ หรือ 5W1H (ใคร/อะไร/ที่ไหน/เมื่อไร/ทำไม/อย่างไร) | EV อ่อน แล็บเดียว [VernonHocking2014] |
| **ติด / ไอเดียไม่มา** | Incubation: ทำงาน low-demand ก่อน (render, จัดไฟล์) แล้วกลับมา | EV d≈0.29 [SioOrmerod2009] |
| **หาจุดอ่อนของไอเดีย** | Reverse brainstorm ("ทำยังไงให้คลิปนี้น่าเบื่อที่สุด?") → กลับด้าน | CRAFT (สัมพันธ์กับ pre-mortem ใน M41) |

## 3. สูตร "3 ทิศทางที่ต่างจริง" (กัน AI sameness)
1. **เขียน "ค่าเริ่มต้น" ก่อน 1 บรรทัด** — ไอเดียแรกที่โผล่มา (มักเป็นค่าเฉลี่ยของโมเดล) แล้ว *ห้ามใช้* เป็นทิศทางใด ๆ ใน 3 ทาง — CRAFT จาก [Meincke2024] (ไอเดียจาก prompt ธรรมดาลู่เข้าค่าเฉลี่ย)
2. **ลิสต์ 8–10 แนวสั้น ๆ (หนึ่งบรรทัด/แนว) ก่อนขยายตัวไหน** — EV chain-of-thought แบบนี้เพิ่มความหลากหลายมากสุด [Meincke2024]
3. **ล็อกแกนความต่าง:** 3 ทางต้องต่างกันอย่างน้อย 2 ใน 4 แกน — *อารมณ์/โทน* (อบอุ่น · ตลก · ลุ้น), *โครงเรื่อง* (ปัญหา-แก้ · พลิกจบ · วนกลับ), *มุมภาพ/สไตล์*, *บทบาทของแว่น* (ฮีโร่ · พร็อพเงียบ · มุกตลก) — CRAFT
4. **ร่างแยกกัน:** เขียนทิศทาง B โดยไม่ดู A, C โดยไม่ดู A/B — EV [Girotra2010; DiehlStroebe1987]
5. **เทียบกับของเก่า:** เช็ก 10–20 ชุดล่าสุดใน `carousel/kits/` / LEARNING-LOG — ถ้าชื่อ/ฉาก/ข้อคิดซ้ำ เปลี่ยน — CRAFT (ตอบโจทย์ homogenization [DoshiHauser2024])
6. **ทางที่ 3 = ทางเสี่ยง:** อย่างน้อย 1 ทางที่ "อาจไม่เวิร์ก" แต่ไม่เหมือนที่เคยทำ — CRAFT (best idea มาจากความแปรปรวน ไม่ใช่ค่าเฉลี่ย [Girotra2010])
7. **ทำหยาบทั้ง 3 พร้อมกัน** (logline + 1 thumbnail/ภาพ HTML ร่าง) ก่อนขัดตัวที่ชนะ — EV [Dow2010]
8. **รูปภาพ:** เปลี่ยน seed + เปลี่ยนคำบรรยายองค์ประกอบ ไม่ใช่แค่ seed; ถ้าเป็นไปได้ใช้คนละโมเดล (FLUX vs Codex) สำหรับคนละทาง — CRAFT จากข้อเสนอของ [Meincke2024]

## 4. วิธีเลือก (convergent)
เขียนเกณฑ์ **ก่อน** อ่านตัวเลือก (กัน anchoring — M41) ให้คะแนน 1–5 แล้วเลือกตัวที่รวมสูงสุด *หรือ* ตัวที่ชนะข้อ 1–2 ขาด:

| # | เกณฑ์ | น้ำหนัก | ที่มา |
|---|---|---|---|
| 1 | **ตรงโจทย์/ผู้ชม** — คนไทยดูแล้วเข้าใจใน 2–3 วินาทีแรก/สไลด์แรก | ×2 | CRAFT + attention ใน `../cognitive-science` |
| 2 | **ความใหม่เมื่อเทียบกับของเราเอง** — ไม่ซ้ำ 20 ชุดหลัง | ×2 | CRAFT (homogenization) |
| 3 | **แว่น/แบรนด์เด่นตามกฎบ้าน** (คลิปสินค้า) หรือ **ไม่มีโลโก้** (Slowly Growing) | ×1 | house rules |
| 4 | **ทำได้จริง** ด้วย pipeline + โควตาที่มี (TTS, Codex) | ×1 | M41 reference class |
| 5 | **ความจริง/ไม่หลอก** — ผ่าน PRE_DELIVERY_CHECK ข้อ 2 & 5 | ผ่าน/ไม่ผ่าน | M41 |

- กลุ่มมักเลือกไอเดียที่ปลอดภัย การมีเกณฑ์ชัดช่วย — EV [Rietzschel2006 (bibl.)]
- เสนอผู้ใช้: **3 ทาง + ตัวที่แนะนำ + เหตุผล 1 บรรทัดต่อเกณฑ์** ให้ผู้ใช้ตัดสินสุดท้าย — CRAFT

## 5. ระวัง
- ทุกวิธีตั้งชื่อ (six hats, SCAMPER, design thinking) มีผลเล็กหรือหลักฐานอ่อน; training โดยรวม ~0.3 SD หลังแก้ publication bias [SioLortieForgues2024] — ใช้เป็นเครื่องมือ ไม่ใช่คำสัญญา
- ความต่างที่วัดได้ ≠ ความดี: ทางที่ต่างที่สุดต้องผ่านเกณฑ์ 1 ด้วย
- ห้ามทิ้งความสม่ำเสมอของซีรีส์ (ตัวละคร, ลายเส้น, กฎบ้าน) เพื่อความใหม่ — ความต่างอยู่ที่เรื่อง/มุม ไม่ใช่ตัวตนแบรนด์
