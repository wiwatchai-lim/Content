# CRITIQUE PROTOCOL — แยก "ผิดทางเทคนิค" ออกจาก "รสนิยม"

เป็นชั้นบน (meta-layer) ของ `.claude/skills/ai-visual-artist/IMAGE_CRITIQUE_ENGINE.md` — engine นั้นบอก **จะตรวจอะไร** (11 ขั้น, severity, คะแนน 100);
ไฟล์นี้บอก **จะจัดประเภทคำวิจารณ์อย่างไร และจะตัดสินอย่างไรให้ยุติธรรม** ใช้ได้กับภาพนิ่ง คลิป carousel เลย์เอาต์ ทุกสาขา
key ใน `[ ]` อยู่ใน `sources.json` ของโมดูลนี้ หรือ `../neuroaesthetics/sources.json`

## 0. ทำไมต้องแยก
- **รสนิยมแตกต่างเป็นเรื่องปกติและวัดได้:** คนเห็นตรงกันสูงเรื่องใบหน้า/ทิวทัศน์ แต่ต่างกันมากเรื่องสถาปัตยกรรมและงานศิลป์ `[Vessel2018]`; ภาพที่ "ซึ้ง" แทบไม่ตรงกันระหว่างคน (r = .13) `[VesselStarrRubin2012]`; เว็บที่ได้รางวัลยังมีคนไม่ชอบเยอะ `[Reinecke2013]`; ความชอบความซับซ้อนแบ่งเป็นกลุ่มตรงข้าม `[GucluturkJacobsVanLier2016]`
- **นักวิจารณ์ก็มี bias:** ผู้ฝึกศิลปะให้คะแนน asymmetry/ความซับซ้อนสูงกว่าคนทั่วไป `[Weichselbaum2018]` `[VanGeertWagemans2020]`; ป้ายบริบท ("พิพิธภัณฑ์", "คนทำ", "AI") เปลี่ยนการตัดสินทั้งที่ภาพเหมือนเดิม `[ChatterjeeVartanian2014]` `[Bellaiche2023]`; การเห็นซ้ำเพิ่มความลื่น/ความชอบ (คนทำงานที่ดูภาพตัวเอง 50 รอบจึงประเมินสูงเกิน) `[ReberSchwarzWinkielman2004]`
- **ปรัชญาให้กรอบ:** Kant แยก "ชอบ" (agreeable) ออกจาก "งาม" และแยก free beauty (ไม่ขึ้นกับหน้าที่) ออกจาก adherent beauty (ขึ้นกับว่าวัตถุ "เป็นอะไร/มีไว้ทำอะไร") — ภาพเชิงพาณิชย์คือ adherent: ตัดสินเทียบจุดประสงค์ `[SEP_KantAesthetics]`. Hume: นักวิจารณ์ที่น่าเชื่อคือผู้มี "ประสาทรับรู้ละเอียด ฝึกฝน เปรียบเทียบ และปลอดอคติ" และยอมรับว่ามีความเห็นต่างที่ "ไม่ผิด" (blameless) จากนิสัย/วัฒนธรรม `[SEP_HumeAesthetics]` → protocol นี้จึงบังคับ **การเปรียบเทียบ** และ **การลดอคติ** และไม่พยายาม "แก้" ความต่างที่ blameless

## 1. สามชั้นของคำวิจารณ์ (ทุก issue ต้องติดป้ายชั้น)

| ชั้น | นิยาม | การทดสอบ (ถามตัวเอง) | ตัวอย่าง | ใครตัดสิน |
|---|---|---|---|---|
| **T — Technical** | ผิดเกณฑ์ที่วัดได้/ฟิสิกส์/ความถูกต้องของข้อมูล/brief ที่บังคับ | "ผู้ตัดสินที่มีคุณสมบัติ 2 คนจะเห็นต่างได้ไหม?" → **ไม่ได้** | แว่นงอ/สะพานเกิน, นิ้วเกิน, ภาษาไทยสะกดผิด, contrast ข้อความ < 4.5:1, ทิศแสง 2 ทางขัดกัน, สีสินค้าไม่ตรงของจริง, ตัดพื้นมี halo, ข้อความตกนอก safe zone, ข้อมูลราคาผิด | checklist / เครื่องมือวัด |
| **C — Contextual (fit)** | ถูกหรือผิด **เมื่อเทียบจุดประสงค์ กลุ่มเป้าหมาย แพลตฟอร์ม ประเภทงาน** | "ถ้าเปลี่ยนจุดประสงค์/กลุ่มเป้าหมาย คำตัดสินนี้กลับข้างไหม?" → **กลับได้** | ป้ายราคาแดงตัวโต: ถูกสำหรับโพสต์โปร ผิดสำหรับลุค premium `[Puccinelli2013]`; ความเรียบ: premium สำหรับของสุขภาพ แต่ไม่สำหรับของตามใจปาก `[Ton2023]`; มืดแบบหนัง: ดีบนจอใหญ่ แย่บนมือถือกลางแดด | brief + LOOK_DICTIONARY + หลักฐาน |
| **P — Preference (taste)** | ทั้งสองทางทำงานได้ตามจุดประสงค์ เหลือแค่ความชอบ | "ทั้ง 2 version ผ่าน T และ C หรือยัง?" → **ผ่านทั้งคู่** | โทนเขียวหรือฟ้า (เมื่อทั้งคู่ harmony ดี), เส้นหนาหรือบาง, เอียง 3° หรือตรง | ผู้ใช้ (USER_PREFERENCES.md) หรือ A/B กับคนจริง |

กฎ: **อย่าเขียนคำวิจารณ์ชั้น P ด้วยภาษาชั้น T** (ห้าม "ผิด", "ต้อง") — ใช้ "ทางเลือก", "ถ้าอยากให้ … ลอง …"

ความสัมพันธ์กับ severity ของ IMAGE_CRITIQUE_ENGINE: critical/major มักเป็น T หรือ C; polish มักเป็น P. ถ้าเจอ "critical" ที่เป็น P → จัดประเภทผิด ให้ทบทวน

## 2. ขั้นตอน (ทำตามลำดับ)

### Step 0 — กำหนดกรอบก่อนดูภาพ (กันอคติ)
1. จุดประสงค์ 1 ประโยค (ขาย/อธิบาย/ทำให้ซึ้ง/ให้หยุดเลื่อน), กลุ่มเป้าหมาย, แพลตฟอร์มและขนาดจอ, คำลุค 1–3 คำ (แปลงเป็น feature ด้วย `LOOK_DICTIONARY.md`)
2. เลือก **reference set** 2–4 ภาพ (งานดีในประเภทเดียวกัน + งานก่อนหน้าของซีรีส์) — Hume: "perfected by comparison" `[SEP_HumeAesthetics]`
3. บันทึกว่าใครวิจารณ์ (claude / ผู้ใช้ / เพื่อน) และเคยเห็นภาพนี้กี่รอบ (exposure bias) `[ReberSchwarzWinkielman2004]`

### Step 1 — Formal analysis: บรรยายก่อน ไม่ตัดสิน
บรรยายสิ่งที่เห็นด้วยคำที่วัดได้ (ยังห้ามใช้ "สวย/ไม่สวย"):
- value key + การกระจาย value (3–4 มวล?), chroma และจำนวน hue, จุดที่ contrast สูงสุด
- composition: จุดสนใจ 1st/2nd/3rd (thumbnail 150 px + เบลอ), negative space %, balance, order (grid/alignment/ซ้ำ)
- density: นับกลุ่มองค์ประกอบ; feature complexity (รายละเอียดดิบ) vs design complexity (ไอเดียการจัดวาง) `[Pieters2010]`
- type: ตระกูล น้ำหนัก ขนาดสัมพัทธ์ จำนวนฟอนต์ ระยะ
- light/material: ทิศ ความนุ่ม อุณหภูมิ ความสม่ำเสมอระหว่างวัตถุ
- motion (คลิป): ความยาวช็อต ปริมาณการเคลื่อนไหว จังหวะตัด `[Cutting2011]`
เครื่องมือ: `python .claude/skills/ai-visual-artist/tools/analyze_image.py` (saliency, balance, notan), ขนาดไฟล์ PNG เป็น proxy ความซับซ้อนเมื่อเทียบ variant `[GucluturkJacobsVanLier2016]`

### Step 2 — Technical pass (ชั้น T)
รัน 11 ขั้นของ IMAGE_CRITIQUE_ENGINE แต่ **บันทึกเฉพาะ issue ที่ผ่านการทดสอบชั้น T** (ข้อ 1). ทุก T-critical ต้องแก้ก่อนคุยเรื่องอื่น — ไม่มีลุคไหนชดเชยแว่นผิดรูปหรือคำไทยผิดได้

### Step 3 — Contextual analysis (ชั้น C)
ถามทีละข้อ แล้วผูกกับหลักฐาน:
1. **Fit กับจุดประสงค์ (adherent beauty):** ภาพทำหน้าที่ที่ตั้งไว้ไหม? ข้อความหลักอ่านได้ใน < 1 วินาทีบนมือถือไหม? (first impression เกิดใน 17–500 ms และความซับซ้อนสูงทำให้ตก `[Tuch2012]` `[Reinecke2013]`)
2. **Fit กับลุคที่สั่ง:** เทียบ feature จาก Step 1 กับ LOOK_DICTIONARY — ต่างตรงไหน และ "พังเมื่อ" ข้อไหนเกิดขึ้น
3. **Fit กับกลุ่มเป้าหมาย/วัฒนธรรม:** รหัสภาพ (white space = prestige, แดง = ดีล) เป็น convention ที่เรียนรู้ `[Pracejus2006]` — กลุ่มนี้ใช้รหัสเดียวกันไหม? ถ้าไม่รู้ ให้ระบุว่า "ไม่รู้" ไม่ใช่เดา
4. **Fit กับซีรีส์/แบรนด์:** typical พอให้จำได้ + ใหม่พอให้สนใจ (MAYA) `[Hekkert2003]`; novelty มีมือจับให้เข้าใจไหม `[Silvia2005]`
5. **Provenance/framing:** caption, label, AI disclosure จะเปลี่ยนการรับรู้อย่างไร `[Bellaiche2023]` `[KoningVoorveld2025]` — ซื่อสัตย์ไหม?

### Step 4 — Comparative analysis
1. วางภาพข้าง reference set ที่ขนาดจริงของแพลตฟอร์ม (เช่น 1080×1350 ย่อเหลือขนาดในฟีด) และที่ thumbnail
2. ถ้ามี 2+ variant: เทียบ **แบบ blind** (ซ่อนชื่อไฟล์/ป้าย "AI"/"ฉบับใหม่") เพื่อกันผลของ label `[Bellaiche2023]` `[ChatterjeeVartanian2014]`
3. เปลี่ยนตัวแปรทีละตัวเมื่อทดสอบ (พื้นหลัง หรือ ฟอนต์ หรือ palette) — ไม่งั้นไม่รู้ว่าอะไรทำให้ต่าง
4. ถามว่า "ภาพนี้แพ้ reference ตรงไหน เพราะอะไร" — ระบุเป็น feature (Step 1) ไม่ใช่ความรู้สึก

### Step 5 — Judgement (ตัดสินแบบแยกชั้น)
ผลลัพธ์ 3 ส่วน:
- **T:** ผ่าน/ไม่ผ่าน + รายการแก้ (บังคับ)
- **C:** ทำงานตามจุดประสงค์ระดับไหน + เหตุผลที่อ้างหลักฐาน/ป้าย evidence (EVIDENCE/DERIVED/CRAFT)
- **P:** ทางเลือกตามรสนิยม เสนอเป็นตัวเลือก ไม่ใช่คำสั่ง → ส่งให้ผู้ใช้เลือก หรือ A/B กับคนจริง และบันทึกผลลง `creative-intelligence/USER_PREFERENCES.md` / experiments
คะแนน 100 จาก `.claude/skills/ai-visual-artist/tools/score.py` คือความเห็นของผู้ประเมิน ไม่ใช่หลักฐานว่าคนดูจะชอบ (engine ระบุไว้แล้ว)

## 3. รูปแบบบันทึก (ต่อยอด `critique` array ของ VISUAL_QUALITY_SCHEMA)
เพิ่ม 2 ฟิลด์จากของเดิม (area · where · problem · severity · likely_cause · fix · side_effects):
```json
{"area":"color","where":"price tag, bottom-right","problem":"red 72px price tag pulls a premium post toward discount coding",
 "severity":"major","layer":"C","evidence":"EVIDENCE Puccinelli2013 + CRAFT",
 "likely_cause":"promo template reused","fix":"neutral small price or move price to caption","side_effects":"weaker deal signal"}
```
- `layer`: `T` | `C` | `P`
- `evidence`: ป้าย + key (หรือ "CRAFT" ถ้าเป็นธรรมเนียมช่าง) — ห้ามเขียนว่า "งานวิจัยบอก" ถ้าเป็น CRAFT

## 4. ตัวกรองอคติ (เช็คก่อนส่งคำวิจารณ์)
| อคติ | อาการ | วิธีกัน |
|---|---|---|
| expert taste | ชอบความซับซ้อน/ไม่สมมาตรมากกว่าลูกค้า `[Weichselbaum2018]` | ถาม "กลุ่มเป้าหมายจะเห็นแบบนี้ไหม?" + A/B |
| exposure / familiarity | ภาพที่ทำเองดูดีขึ้นเรื่อย ๆ เพราะเห็นบ่อย `[ReberSchwarzWinkielman2004]` | พักแล้วดูใหม่, ให้คนที่ไม่เคยเห็นดู 1 วินาที |
| label / provenance | รู้ว่า AI ทำ → ให้คะแนนต่ำ; รู้ว่ามืออาชีพทำ → สูง `[Bellaiche2023]` | blind comparison |
| averaging fallacy | "คนส่วนใหญ่ชอบกลาง ๆ" ทั้งที่มี 2 กลุ่มตรงข้าม `[GucluturkJacobsVanLier2016]` | ระบุกลุ่มผู้ชมก่อนสรุป |
| neuro / science halo | อ้างสมอง/กราฟให้ดูน่าเชื่อ `[DragicevicJansen2018]` `[Turner2018]` | ใช้ป้าย evidence บังคับ |
| single-judge | คำตัดสินจากคนเดียว | Hume "joint verdict": อย่างน้อย 2 ความเห็น หรือข้อมูลจริง (saves, comments) `[SEP_HumeAesthetics]` |

## 5. ตัวอย่างสั้น (ทั่วไป)
**ภาพ:** โพสต์สินค้า (แว่น/นาฬิกา/เครื่องสำอาง ได้หมด) สั่งลุค "premium" — พื้นขาว สินค้า 4 ชิ้นเรียงแน่น ราคาแดงตัวใหญ่ ฟอนต์ 3 แบบ
- T: ชิ้นที่ 3 ตัดพื้นมี halo (T-major); คำไทยตัดบรรทัดผิด (T-critical)
- C: สินค้าเบียด → ลด prestige `[Sevilla2016]`; ราคาแดง → รหัสดีล `[Puccinelli2013]`; 3 ฟอนต์ → ขัด congruity `[DoyleBottomley2006]` (DERIVED) ⇒ ไม่ fit กับ "premium" แต่ **จะ fit** ถ้าจุดประสงค์คือโปรล้างสต็อก
- P: พื้นครีม vs พื้นขาว — ทั้งคู่ผ่าน → เสนอเป็นตัวเลือก หรือ A/B
