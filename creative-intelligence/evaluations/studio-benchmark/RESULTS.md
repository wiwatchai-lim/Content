# Studio Benchmark v1 — before vs after (2026-11-26)

Raw table: `RESULTS_TABLE.md` (generated by `blind.py score`). Judge files: `runs/judge/*.json`. Blind map: `_key/blind_map.json`.
**All scores are AI-judge scores against an answer key — not human ratings.**

## Set-up
- 24 tasks: 8 critiques (65 scored planted defects, 36 critical), 12 decisions (49 key points), 4 creative briefs.
- "baseline" = system before the upgrade (frozen `runs/baseline.sha256`); "after" = with domain guides, Creative Memory,
  creative-critic, routing changes (`runs/after.sha256`). Same solver prompt (`SOLVER_PROMPT.md`), fresh agents, one run each.
- 5 judge agents, answers relabelled X/Y at random per task; create tasks judged twice in opposite reading orders.

## Results
| area | baseline | after | difference |
|---|---|---|---|
| Critique: planted defects found | 64.5 / 65 (99%) | 64.0 / 65 (98%) | none (−0.5 = one partial item in C3) |
| Critique: critical defects found | 36 / 36 | 36 / 36 | none |
| Critique: invalid extra findings (padding / wrong rules) | 5 | 1 | **fewer false alarms** |
| Critique: fix / reason quality (0–2) | 1.98 / 1.94 | 1.99 / 2.00 | negligible |
| Decisions: key points | 91 / 98 (93%) · 1 wrong claim | 95 / 98 (97%) · 0 wrong claims | **+4 points** (D3 voice choice, D12 recording feedback) |
| Create: rubric mean (1–5) | 4.53 | 4.66 | +0.13 |
| Create: pairwise (both orders must agree) | G2 | G1, G3 | after 2 · baseline 1 · tie 1 (G4 split) |

## What the numbers support
1. **Critique recall did not improve — because it could not:** the baseline already found 99% of planted defects. The
   benchmark is at ceiling for rule-based defects (house rules were already in CLAUDE.md and the skills).
2. **Precision improved:** invalid extra findings 5 → 1 (critic rules: locate, justify, no padding, novelty ≠ error).
3. **Decisions about memory and characters improved:** D12 (what to record after an approval) 7 → 10 of 10 and D3
   (new character voice) 6 → 7 of 8 with one false claim removed. These map directly to Creative Memory and the
   character records.
4. **Creative work:** one clear win in both reading orders (G1 story carousel: less preachy, real reframe, flagged the
   Mint/Tao outfit question), one clear win (G3), one clear loss (G2 product clip, near-tie: 4.93 vs 5.00), one split (G4).
   Not enough to claim a general creative improvement.

**Honest summary:** small, real gains in precision and in memory-dependent decisions; no measurable gain in defect recall
(ceiling); creative quality mixed-to-slightly-better on 4 tasks. No claim of large improvement is supported.

## Limits (read before quoting any number)
- One run per system; no variance estimate. AI judges (same model family as the solvers → self-preference risk).
- Answers can reveal their system (e.g. "inline (not independent)", domain citations), so blinding is partial.
- The after-run solver's search accidentally surfaced one line of the key (D8) and of baseline D8/G1; it reported this
  itself. D8 scored 8/8 for both systems, so the totals are unchanged by excluding it.
- The after-run solver wrote critiques inline instead of launching the independent critic sub-agent; the critic pipeline
  was tested separately (end-to-end run, see `UPGRADE_LOG.md`).
- The key was written by the same author as the upgrade; it uses rules that existed before the upgrade to limit bias.

## Next benchmark (v2) — needed to measure the new knowledge
The v1 tasks reward house rules both systems knew. v2 should test what only the domain guides add, e.g.:
subtle unintended symbols (05), metaphor freshness and Thai rhythm (08), loudness/masking misconceptions (10),
persuasion that backfires (11), AI-judge bias traps such as a longer-but-worse answer (12/13), continuity across 5+
episodes (07), safe messaging on loneliness (02). And it needs **human ratings from the user** on real outputs — the only
way to move any module past PRACTICALLY TESTED.
