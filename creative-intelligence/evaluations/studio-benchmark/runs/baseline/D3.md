I don't pick a voice by feel. I follow the procedure in the voice bible:

1. **Check the bible.** A `ton` (ต้น, ร้านแว่นตีสอง) already exists, with **Puck as an unauditioned proposal** (`locked: false`). If this is that Ton, I reuse his profile. If it is a different "ต้น" in another series, he gets a series-prefixed id (e.g. `zombie_ton`) so the two are never mixed, and I fill every row: age, pitch, range, particles (ครับ/ผม), habits, consistency rules.
2. **Shortlist 2–3 Gemini prebuilt male voices** from the *current* docs list; I don't invent names. Puck goes first because it has been heard in this project (Thai male promo). The other one or two must not already be in use in the same series:
   - not Charon, the narrator: in EP01 the characters and the narrator sounded alike, which is exactly what to avoid;
   - not the other male characters' voices (Algenib, Umbriel).
3. **Audition** the same three test lines (neutral, happy, sad) in **one request per voice**, all on one model (`gemini-3.1-flash-tts-preview`). I ask the user before generating: each request uses the daily Gemini quota of about 10.
4. **Lock the user's choice.** The user, as the native listener, picks. Then I set `locked: true`, write `voice_by_provider.gemini`, record the neutral-take baseline with `tools/analyze_audio.py`, sync the JSON block and run `tools/validate.py`. Until the user approves, Puck stays a proposal.
